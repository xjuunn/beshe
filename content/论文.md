# 基于Web的校园百货零售网站设计与实现

----

## 1 绪论

### 1.1 研究背景与意义

从用户角度出发，电子商务在年轻群体中快速普及，而校园零售的传统模式已经显得落后，效率低、体验差，无法满足学生对快速浏览、便捷支付和高效配送的期望。通过本课题的研究与实现，校园用户可以轻松地浏览商品、管理购物车、完成订单支付，从而提升校园用户地购物体验。

从管理角度看，零售管理地效率决定了服务质量，一个没有数据驱动、流程混乱的管理后台，只会让运营者手忙脚乱。这时候，一个具有商品分类、库存监控、订单处理和销售统计功能的后台管理系统显得尤为重要。对数据统计分析同时，管理者还可以深入了解消费趋势，帮助管理者实现精细化运营，为未来的优化和决策提供可靠依据。

更重要的是，在数字化浪潮的今天，智慧校园的概念已经被越来越多的高校接受，而零售的数字化转型是智慧校园不可或缺的一环。通过使用Vue3和Spring Boot这些技术，不仅在技术上保持先进性，还为系统的扩展性和性能提供了坚实保障。

技术的价值在于解决问题，创新的核心是服务用户。总之，本课题通过构建一个功能完善、操作简便的校园百货零售网站，满足用户多样性的需求，提升零售管理效率，推动校园零售数字化和智能化的发展。这将为高效师生的日常生活提供便利，并为校园经济建设做出积极贡献。



### 1.2 国内外研究现状

在过去的几年里，电商行业的发展已经不再局限于传统的大型平台，它已经擅入到每个行业，每个生活场景中。尤其是在校园零售这个领域，随着大学生消费需求的多样化和技术的进步，市场规模越来越大，而通过Web技术构建的校园百货零售平台，正是一个非常具备潜力的平台。从或内外的现状来看，校园零售电商正处于迅速发展的阶段，并逐渐趋向于多元化和智能化。

在国内，校园电商的快速崛起得到了多方关注。近年来，饿了么发布了“数字校园生态联盟计划”，宣布全面升级“智慧校园”数字化服务，进而推动校园即时电商市场的发展。根据饿了么发布的数据，过去一年来自高校的订单已经突破了10亿单，校园用户订单增长速度超过整体外卖用户的平均增速。尤其是在“后疫情时期”，校园消费需求迅速增长，学生对外卖的需求已经不再仅限于餐饮，甚至涵盖了零售、美妆、娱乐等多元化领域。这一变化反映出，校园消费市场规模已经达到了“万亿”级别，市场增量空间巨大。由此，数字化服务的全面升级和校园电商平台的进一步发展，已经成为提升学生生活品质的重要因素。

此外，天猫也在高校市场深耕，推出了全国首个天猫校园店，在四川师范大学开设了新的零售实体店。并通过大数据分析精准匹配商品和用户需求，从而提升了商业运营的效率。根据天猫的计划，未来将继续扩展校园零售店铺，计划在三年内进驻全国1000所高校，服务超2000万高校人群。

国外关于基于Web的零售网站发展，正处于快速变化和创新的关键阶段，在用户功能方面，个性化推荐、智能搜索和便捷支付已经成为标配，国外很多企业通过不断地技术迭代，成为行业地标杆。在欧洲，电子支付地普及率较高，一些校园平台还集成了校园内地支付系统，使结算更加方便。个性化推荐和智能搜索技术正在快速发展，例如亚马逊等公司采用机器学习算法来提高用户地搜索体验和推荐精度。

电子商务的未来发展趋势表明，个性化服务和数据驱动的运营将成为零售行业的重要方向。本课题的研究通过提供用户评价和反馈功能，不仅能帮助管理者更好的优化服务，还能增强用户的参与感和粘性。此外数据统计分析功能为零售管理者提供了更精准的决策支持。通过提升用户和管理者的满意度有助于构建健康发展的校园经济生态，增强校园经济的活力和可持续性。

## 2 系统需求分析

### 2.1 系统功能需求

该系统采用前后端分离架构，前端使用Vue3构建用户界面，后端使用Spring Boot处理业务逻辑，并通过RESTful API进行数据交互。数据库采用MySQL。系统旨在为校园师生提供便捷的购物体验，同时为管理员提供高效的商品和订单管理工具。

1.   响应式布局：用户和管理员可以在PC端或移动端访问网站，适配不同分辨率的设备，均能获得良好的跨设备体验。
2.   账户管理：支持用户的注册、登录操作，对用户的密码进行加密保存，保证账号的安全和用户的隐私。
3.   商品管理：提供商品的添加、删除、修改、分类、库存监控的功能。使管理员便捷的管理和监控商品的状态，保证系统的稳定运行和商品的正常运营。
4.   购物：用户可以浏览商品，通过分类或者关键词搜索想要的商品，用户可以查看商品的详细信息，选择购买数量，加入购物车，购买支付等操作，保证用户的便捷性。
5.   订单管理：用户可以创建订单，管理员可以对订单进行管理，包括订单的删除，订单状态更新等操作。
6.   评价与反馈：购买商品的用户可以对这个商品进行评价，管理员可以管理评价信息，可以删除用户的评价。
7.   数据统计分析：系统自动统计销售数据，生成报表供管理员查看。
8.   安全性：采用身份认证、数据加密、权限管理等措施，无权限的用户无法访问后台页面，用户密码加密存储，未登录用户无法购买商品，用户登录后，过一段时间需要重新登录等，确保系统的安全稳定运行。

### 2.2 用户需求分析

普通消费者主要使用前台功能，设计商品的浏览、支付、订单管理等。

用户可以在主页浏览商品，或者通过关键词搜索商品信息，也可以通过商品分类搜索商品，支持模糊搜索，快速找到目标商品。商品详情页面提供商品的描述、型号、价格、用户评价等信息；用户可以将商品添加到购物车，并可以调整购买数量或移除商品。购物车显示商品的信息、总价格等；用户可以查看和修改个人信息、修改手机号、收货地址等。购买商品后，自动以用户信息的收货地址作为发货地址，支付成功后可以在订单列表查看；用户可以对购买的商品进行评价，包括评分、文字评价等。用户可以查看其他人的评价，了解商品质量。



### 2.3 后台管理员需求分析

后台管理员主要负责管理商品、库存、订单、用户等，确保系统正常的运行。

管理员可以在仪表盘查看系统的总体状态，如在线人数、商品种类和重要通知等功能；查看本月的销量和收入；查看最新的用户评价；低库存的商品列表；商品销量排行和受欢迎商品种类的分析等重要信息，便于管理员快速了解当前的系统运行状态和商品状态等信息，便于管理员快速定位信息，以便及时做出响应。

管理员可以在用户列表页面查看和管理普通用户信息，通过手机号，邮箱和用户名搜索用户。

管理员可以在评价反馈页面查看所有的评论信息，还可以对评论进行删除；

管理员可以在商品列表页面查看所有的商品，分页显示，可以通过商品名查询商品，点击新增商品按钮可以新增商品，可以修改和删除和修改商品信息。

管理员可以在商品分页页面管理所有的商品分类，并通过一定顺序进行排序，管理员可以修改商品分类的顺序，可以新增商品分类，修改商品分类的分类名称和顺序，也可以删除商品分类。

管理员可以在库存警告页面可以查看所有的库存不足的商品，以便管理员快速定位哪些商品库存不足，快速补货。

管理员可以在订单列表页面查看所有用户订单，分页显示，管理员可以查看订单详情，商品详情，用户详情，也可以删除订单。

管理员可以在退款和售后页面查看所有的退款和退货订单，管理员可以对订单给予驳回和通过操作。

## 3 系统开发技术介绍

### 3.1 Vue3框架

Vue3框架是国内最受欢迎的前端框架之一，Vue的核心是响应式数据绑定和组件加开发，它具有易学易用、性能出色、适用场景丰富的Web框架。它基于标准的HTML、CSS、JavaScript构建，并基于组件的形式构建用户页面，简化了数据的管理和数据更新，提高了代码的复用性和可维护性，同时也具有非常好的性能。Vue具有良好的生态系统，功能覆盖了大部分的前端开发常见的需求，使前端系统更加高效，进一步提高了用户的体验，确保想哭具有更好的可维护性和可扩展性。



### 3.2 Spring Boot框架

Spring Boot作为Spring框架的一个快速开发解决方案，它简化了Spring应用的开发和部署，可以快速构建独立的、生产级的Spring应用，而无需繁琐的XML配置。Spring Boot结合了Spring生态系统的强大功能，适用于微服务架构、RESTful API开发、Web应用等多种场景。Spring Boot作为一个轻量级、高性能、易扩展的后端开发框架，并提供了一整套高效的解决方案，能够满足本项目的功能需求，并具备良好的可扩展性，为未来的维护和升级提供便利。



### 3.3 MySQL数据库

MySQL是一种流行的关系型数据库，它基于SQL进行数据库管理，具有高效性、可扩展、稳定、安全等特点，广泛应用于Web开发、电子商务、企业管理等领域。



###  3.4 前后端分离架构设计

本项目采用前后端分离的架构，即前端(Vue)和后端(Spring Boot)独立开发、独立部署，通过API进行通信。这种架构能够提高开发效率、提升系统的扩展性，并支持多终端适配。采用该架构后，前后端解耦，提高开发的效率和可维护性，使系统具备包性能、可扩展、易维护的特点。

本项目主要由以下三个部分组成:

1.   前端：用户界面，负责渲染和交互逻辑
2.   后端：提供API接口，负责业务逻辑处理，数据库操作等。
3.   数据库：存储业务数据，如用户、商品、订单等。

## 4 系统总体设计

### 4.1 前端系统架构设计

前端系统采用Vue3 + Nuxt3 进行开发，并结合Pinia、Axios、DaisyUI进行页面渲染、状态管理、API交互和UI框架支持。

技术选型：

| 技术        | 说明                                                         |
| ----------- | ------------------------------------------------------------ |
| Vue3        | 轻量级、响应式前端框架                                       |
| Nuxt3       | 快速开发框架，减少配置                                       |
| Vite        | 高速构建工具，提升开发效率                                   |
| Pinia       | 轻量级状态管理工具，替代Vuex，比Vuex更轻量，更简单，支持组合式API |
| Axios       | HTTP请求库，与后端交互                                       |
| TypeScript  | 提高代码的可读性和可维护性                                   |
| TailwindCSS | 原子化CSS框架，减少CSS代码冗余，提高开发效率                 |
| DaisyUI     | 基于TailwindCSS的UI组件库，提供丰富的主题和组件，提升UI设计美观度 |

本系统采用前后端分离架构，前端基于Vue3开发，整体架构如下：

*   页面层(pages)：`pages`目录用于自动路由，组织页面结构。
*   组件层(components)：拆分常用UI组件和业务组件，复用性强。
*   状态管理层(stores)：使用Pinia管理全局状态，保证数据共享。
*   API请求层(api)：封装API请求，对请求代码统一进行管理。
*   布局层(layouts)：前后台使用不同的布局。

采用文件系统路由，直接使用文件路径作为路由路径，支持动态路由。使用JWT进行用户身份验证，登录后token存储在Pinia和localStorage，在守卫中拦截未登录和无权限用户，跳转到登录页面和无权限页面。使用TailwindCSS适配不同分辨率设备，在不同设备上都能看到舒适的用户界面。封装Axios，让每次请求携带token，并且在合适的时机刷新token。使用DaisyUI，所有的颜色均使用内置颜色，有利于实现主题的配置，以及实现深色模式和亮色模式切换的功能。

在前端系统中，使用ssr进行在线用户数量的统计和管理。

### 4.3 系统模块划分与功能概述

1.   用户管理模块：前台用户可以登录和注册、获取用户头像，查看自己的账号详情、修改自己的账号信息、上传头像；后台管理员可以删除用户、更新用户、分页查询所有用户列表、通过用户名，邮箱或者手机号搜索用户。
2.   商品管理模块：前台用户可以查看商品列表、查看商品详情、通过关键字或者分类搜索商品、查看商品图片；后台管理员可以新增和删除商品、更新商品信息和修改商品图片、查看库存过低的商品、修改商品库存量。
3.   购物车管理模块：前台用户可以添加商品到购物车、删除购物车、修改购物车商品数量、查看购物车列表。
4.   商品分类管理：前台用户可以获取所有的商品分类；后台管理员可以查看商品分类、修改商品分类、添加商品分类以及删除商品分类、修改商品分类排序字段等功能。
5.   订单管理模块：前台用户可以创建商品订单，查看自己的订单列表、查看订单详情、退货申请和取消订单功能；后台管理员可以查看所有用户的订单、删除订单、批准和驳回退货申请和退款申请。
6.   评价管理模块：前台用户可以对自己购买的商品进行评价、可以查看某个商品的评价列表；后台管理员可以查看所有的商品评价信息、删除某个评价、查看最新的几条评价。
7.   销售管理模块：前台用户可以创建自己的购买记录；后台管理员可以查看所有的销售记录、查看销售总额和销售数量、查看销售排行、查看本月销售额。

### 4.5 系统流程与交互设计

本系统用户在前端通过Vue3进行交互，前端使用Axios发送http请求和后端接口对接，后端对请求进行处理，然后返回数据库的数据。前端通过Pinia状态管理维护全局数据，如用户数据信息、购物车、系统信息。系统整体交互流程如下：

1.   用户访问网站：用户进入首页，可以查看商品首页的商品分类、商品列表、通过关键词和商品分类搜索商品。
2.   用户注册和登录：未登录用户可以点击登录按钮或者注册按钮跳转到对应的登录和注册页面，用户可以使用用户名和密码进行登录，或者输入用户名和密码，上传用户头像文件后注册账号。后端通过对数据进行验证，登录成功后，返回JWT TOKEN，存储与Pinia和localStorage中，后续的所有请求都携带这个TOKEN。
3.   购物：用户通过关键词或者分类搜索商品，找到对应的商品，点击商品详情，进入商品详情页，用户可以选择购买数量，之后加入购物车。在购物车中也可以修改购买的商品数量，之后可以查看商品详情，删除购物车和下单功能，购物车可以自动计算出订单的总金额并生成对应的订单。
4.   用户评价与反馈功能：用户可以在订单页面对商品进行评价，可以使用星级对商品进行打分。
5.   订单处理：在我的订单页面可以查看所有的订单，可以查看订单状态，申请退货和取消订单等功能。
6.   修改个人信息：用户点击左上角用户头像，展开用户菜单，点击设置，打开设置页面，用户可以对个人信息进行修改和保存，点击用户头像，可以上传用户头像。

后台管理员操作流程如下：

1.   登录系统：管理员通过前台的登录页面登录系统，登录后页面显示后台管理按钮，点击进入后台管理页面。
2.   仪表盘：管理员登录后台首屏显示仪表盘，仪表盘页面显示当前管理员的用户名，退货申请、商品种类、在线用户量、本月销售量、本月收入、最新评价、库存警告、销量排行、商品分类购买占比等信息：
3.   用户管理：在后台页面左侧点击用户列表（小屏设备需要点击菜单按钮，展开菜单），打开用户列表页面，页面分页展示所有的用户信息列表，点击先修改按钮可以修改用户信息，点击删除按钮可以删除用户，在列表上分的搜索栏搜索用户名、用户邮箱、用户手机号可以搜索对应的用户，点击重置，重置搜索条件并显示所有用户列表。
4.   评价管理：在后台页面左侧点击评价反馈（小屏设备需要点击菜单按钮，展开菜单），打开评价反馈展示所有评价信息列表，点击查看可以查看商品信息以及评价详情。点击删除可以删除对应的评价。
5.   在后台页面左侧点击商品列表（小屏设备需要点击菜单按钮，展开菜单），商品列表分页显示所有商品列表，点击修改可以修改商品信息，商品图片等，点击删除可以删除当条商品，在列表上方可以输入商品名，进行模糊查询搜索对应的商品信息，点击重置按钮可以重置搜索条件并显示所有商品列表。点击新增商品可以输入商品信息后新增商品。
6.   在后台页面左侧点击库存预警（小屏设备需要点击菜单按钮，展开菜单），库存预警显示所有库存不足的商品，点击修改按钮可以对商品进行补货，点击删除可以删除对应的商品信息。
7.   在后台页面左侧点击订单列表（小屏设备需要点击菜单按钮，展开菜单），订单列表分页显示所有用户订单，点击查看可以查看当条订单的的订单信息，商品信息和用户信息，点击删除可以删除某条订单。
8.   在后台页面左侧点击退款和售后（小屏设备需要点击菜单按钮，展开菜单），退款和售后页面显示所有的退款申请、退货申请的订单，点击通过可以对订单商品进行退款和退货，点击驳回可以驳回申请。

### 5.2 用户注册与登录功能

用户注册与登录功能是本系统的基础功能，主要用于用户身份管理，确保用户能够安全访问系统。本系统采用JWT(JSON Web Token) + Pinia + localStorage实现身份验证，前后端分离，前端负责用户交互，后端负责数据存储和身份验证。

前端用户输入用户名和密码，使用Axios发送HTTP请求，后端接收到请求后，对请求的用户名和密码进行验证，对密码进行加密后和数据库中的密码进行比对，验证成功后，对前端返回Token以及用户信息，前端收到后将token和用户数据存储到Pinia中，然后将token和用户数据存储到localStorage中，防止刷新页面后数据丢失。每次页面初始化时首先从localStorage中获取token和用户数据，如果数据存在，则存储在Pinia中，方便快速读取信息。

同时用户注册页面显示头像选择按钮，点击后可以选择用户头像图片文件。

用户登录后，所有请求将携带token发送，便于进行身份验证和权限管理。

~~~ ts
// 在localStorage中获取token
let getToken = (): string => {
  if (import.meta.client) { // 防止在服务器ssr环境中运行
    let token = localStorage.getItem('token'); // 在localStorage中获取token
    if (token) return token; // 如果token存在 返回token
  };
  return 'no token'; // 如果token不存在，则返回 ’no token‘
}
let axiosInstance = initAxios(); // axios 实例
// 刷新axios实例，用户登录后需要重新获取token，生成新的axios实例
export function refreshAxios() { axiosInstance = initAxios() }
// 初始化一个axios实例
function initAxios() {
  let instance = axios.create({
    baseURL: '/serverapi',  // 在所有请求前拼接这个字符，用来跨域
    timeout: 10000,  // 超时时间
    headers: {
      "Content-Type": 'application/json',
      "Authorization": getToken(), // 获取token字符串
    },
  });
  instance.interceptors.response.use((response) => {
    return response;
  }, error => {
      // 如果返回的状态码为401，说明用户token无效，自动跳转登录页面
    if (error.response.data.code === 401) {
      createToast(error.response.data.message, { type: 'error', style: 'soft', icon: 'mingcute:safe-lock-fill' })
      navigateTo('/login')
    }
  })
  return instance;
}
// 暴露出useAxios，让外部使用
export const useAxios = () => axiosInstance;
~~~

为了进行跨域请求，需要在前端中配置代理，本项目的做法是配置vite的代理：

~~~ json
proxy: {
  "/serverapi": { // 对所有的带有这个字符串的请求应用代理
    target: process.env.API_BASE_URL,  // 目标服务器地址，存储在`.env`环境变量中
    changeOrigin: true,
    rewrite: (path) => path.replace(/^\/serverapi/, '') // 重写url，去掉代理用的字符串
  }
}
~~~

商品浏览与搜索功能是本系统的核心模块之一，主要设计商品的展示、搜索筛选、分页加载等功能。

使用动态路由显示商品详情，使用`/products/[id]`获取商品的id，进而从后端请求对应的商品信息。

因为商品图片有的是透明背景，有的是白色背景，为了达到样式的统一，可以使用canvas对图片进行处理，将白色背景转换为透明背景，具体操作如下：

~~~ ts
// 传入图片url地址
async function convertWhiteToTransparent(imageUrl: string): Promise<string> {
    // 返回新的图片的url （blob对象的url）的Promise
  return new Promise((resolve) => {
    const image = new Image(); // 创建一个图片
    image.crossOrigin = 'anonymous'; // 跨域
    image.src = imageUrl; // 设置图片url
    image.onload = () => { // 当图片加载时
      // 将图片绘制进Canvas
      const canvas = document.createElement('canvas');
      const ctx = canvas.getContext('2d');
      if (!ctx) return resolve(imageUrl);
      canvas.width = image.width;
      canvas.height = image.height;
      ctx.drawImage(image, 0, 0);
      const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
      const data = imageData.data;
      let hasTransparentPixel = false;
      // 遍历每一个像素，如果存在透明色，则直接返回原图片，防止处理透明背景图片
      for (let i = 0; i < data.length; i += 4) {
        const alpha = data[i + 3];
        if (alpha < 255) {
          hasTransparentPixel = true;
          break;
        }
      }
      if (hasTransparentPixel) {
        resolve(imageUrl);
      } else {
        // 将白色像素转换为透明像素
        for (let i = 0; i < data.length; i += 4) {
          const r = data[i];
          const g = data[i + 1];
          const b = data[i + 2];
          if (r > 250 && g > 250 && b > 250) {
            data[i + 3] = 0;
          }
        }
        // 返回新的透明背景图片
        ctx.putImageData(imageData, 0, 0);
        resolve(canvas.toDataURL('image/png'));
      }
    };
    image.onerror = () => resolve(imageUrl);
  });
}
~~~

### 5.8 商品管理功能

商品管理功能主要用于管理商品的增删改查等操作，确保商品信息的完整性和准确性。管理员可以通过本功能对商品进行维护，包括商品的基本信息、修改商品信息、删除商品、添加商品、搜索商品等功能，以支持前台用户的正常购买流程。

点击列表项的修改按钮，可以对商品进行修改，跳转到`/admin/products/[id]`，页面获取商品id，自动填充对应的商品信息，页面显示商品图片，和新增删除图片按钮，点击加号按钮，打开本地资源浏览器，选择对应的商品图片，即可添加商品图片到商品信息列表，第一图片作为商品封面。修改商品信息后，点击修改按钮，即可提交到后端服务，应用修改；点击取消按钮，即可取消修改，返回商品列表页面。

点击商品列表页面上方的新增商品按钮，即可跳转到新增商品页面，页面显示基本的商品信息和商品图片，点击商品图片取余即可打开本地资源管理器，选择对应的商品图片，即可添加到商品图片列表；也可以从本地资源管理器中直接拖动图片到图片区域，也可以添加图片；支持多选图片，同时拖动添加。输入对应的商品信息后，点击上传，即可发送到后端服务，将商品数据添加到商品列表中。点击重置即可重置表单。

export default defineEventHandler(async (event) => {
  if (await useStorage().getItem('view:num') == null) 
    await useStorage().setItem('view:num', 0)
  return await useStorage().getItem('view:num')

~~~

/server/api/viewadd.ts

~~~ ts
export default defineEventHandler(async (event) => {
  let num = await useStorage().get('view:num');
  if (num == undefined) await useStorage().set('view:num', 0);
  // 将系统中的用户量添加1
  await useStorage().set('view:num', Number(num) + 1);
  return await useStorage().get('view:num');
})
~~~

在每次登录时调用`/api/viewadd`，即可在对系统中的在线数量添加1，仪表盘数据实时更新。

仪表盘数据多且复杂，为了适配不同分辨率屏幕的设备，页面采用响应式布局，在不同的设备查看页面，将调整页面布局顺序、排版和尺寸，以让管理员在不同设备均能看到良好的用户界面。



### 5.15 用户身份验证与权限控制

本系统采用基于JWT的用户身份认证机制，实现用户的身份验证和权限控制。系统中主要分为普通用户和管理员两类，不同的角色用户不同的访问权限，以保证系统的安全性和数据的保密性完整性。

用户身份认证采用账号密码登录方式，结合JWT令牌进行身份标识。用户登录后，后端系统生成toke，将其返回给前端进行存储于Pinia和localStorage，后续的请求需要携带token，以确保身份的合法性。

为了基于用户角色对不同资源进行权限控制，主要包括页面级别权限和API接口权限两部分：未登录用户只能查看前台的首页和全部商品页，无法进行购买商品，对管理后台、购物车、我的订单等按钮进行隐藏；同时，未登录用户；普通用户只能查看前台页面，隐藏管理后台跳转按钮。如果普通用户尝试进入后台管理页面，则返回无权限页面。

使用路由守卫实现页面拦截功能，对没有权限的用户，自动跳转到无权限页面。

~~~ ts
export default defineNuxtRouteMiddleware(async (to, from) => {
    // 如果路由路径中存在admin，则进入判断条件
    if (to.fullPath.includes('admin')) {
        setTimeout(() => {
            if (import.meta.client) { // 确保只在客户端运行
                let user = JSON.parse(localStorage.getItem('user') + ''); // 获取用户信息
                if (!user) return navigateTo('/login'); // 如果用户信息不存在，则跳转到登录页面
                if (user.roleId != 1) return navigateTo('/noPermissions') // 如果用户不是管理员，则拦截请求到无权限页面
            }
        }, 100);
    }
});
~~~
